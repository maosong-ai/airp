# AIRP Notion

面向 [AIRP](https://github.com/maosong-ai/airp) 文档（`*.airp.json`）的 Notion 式客户端：左侧是一列可编辑的块，右侧是**渲染器自己的产物**。

**边写报告，边看它成稿的样子。**

渲染器回答的是"这份文档长什么样"；这个 app 回答的是"**我正在写的时候**它长什么样" —— 而且不去造第二个渲染器。右栏不是仿制品：它就是 `airp-render` 写出的那份字节，通过共享渲染服务取得，所以摆在编辑区旁边的就是你即将保存的那个文件。

没有侧栏。文档本身就是整个界面，其余的东西都出现在你已经在的地方：操作行上的 `/` 菜单，每个块把手后面的块菜单。

## 目前可以做到的事情

### 写

| | |
| --- | --- |
| **46 个块类型** | schema 声明的全部类型，收在一个菜单里。每个块都**按 schema 播种**，所以创建出来的一瞬间就是合法的 —— 不会一上来就是一块红的。 |
| **操作行上的 `/`** | 打开完整菜单。继续输入即过滤，`↑` `↓` 移动，`Enter` 插入，`Esc` 关闭。 |
| **操作行** | 永远存在，且**不属于文档**：它是一个可供操作的入口，永远不会被渲染，在你打字或从它的菜单里选择的那一刻变成一条真实的段落。所以空文档依然有地方可写 —— 而文档依然是**真的空**。 |
| **就地编辑** | 正文类字段就在它被画出来的地方编辑。字段默认一行高，随内容自动增高。 |
| **把手 `⋮⋮`** | 按住即拖，在**同一父级内**重排 —— 被拖的行浮起，经过的行滑开让位。单击则打开块菜单：上移、下移、复制、转为…、删除。 |
| **转为…** | 改变块的类型，并**保留它的文字**。不同类型不共享字段名（提示块的正文叫 `body`，段落叫 `text`），所以内容按"字段在各自类型形状中的位置"搬运。 |
| **重命名** | 双击顶栏里文档的名字。`Enter` 或点击别处提交，`Esc` 放弃；保存出来的文件以它命名。 |
| **撤销 / 重做** | `⌘Z` / `⇧⌘Z`（Windows 为 `Ctrl+Z` / `Ctrl+Shift+Z`）。 |

### 看

| | |
| --- | --- |
| **预览栏** | 经 `@airp/render-service` 渲染，它调用 `@airp/renderer/node/render` —— 与 `airp-render` 命令和 VS Code 扩展背后是**同一个函数**。Mermaid 在 jsdom 里排版、文字度量是打桩的，浏览器直接渲染同一份源码会画出不同的图；这就是预览必须问服务端的原因。 |
| **按固定宽度排版** | 帧按 **960px** 排版（渲染器内容列达到上限的宽度），再缩放适配右栏。渲染器的标记是响应式的，所以"帧跟着右栏走"等于在预览**另一份文档**：1440px 窗口下右栏是 633px，比渲染器的 `sm` 断点低 7 像素，于是显示的是手机版排版。 |
| **是内容，不是整页** | 导出的外壳被隐藏 —— 产品自己的顶栏页脚，以及文档级的协议徽标、标题、"最后更新"行。那些是**页面**的家具，而这个 pane 就在页面内部、页面已经显示了它们：协议版本与文档时间戳改由预览栏自己的头部承担。 |

### 存

| | |
| --- | --- |
| **保存** | `⌘S` 直接写回文档所在的文件，不弹任何对话框。首次保存还没有文件，才会问位置 —— 并建议以文档名命名。 |
| **另存为…** | `⇧⌘S` 总是询问，并把文档**改绑**到新文件。 |
| **打开…** | 读入一份 `*.airp.json` 并绑定它，之后保存就写回这个文件。 |
| **刷新即空白** | 这是设计如此。文档一旦有了文件就以文件为准；文件在哪里是宿主的事，所以句柄不写进 JSON，也不在背后替你持久化任何东西。 |

保存使用 **File System Access API**。没有该 API 的浏览器（Firefox、Safari）退回下载文件，并且状态行会**明说**这一点，而不是假装更新了某个文件。

## 安装与启动

### 1. 环境要求

- Node.js ≥ 20.19、pnpm ≥ 10.17（见仓库根 `package.json`）
- 若要「保存」直接写回文件（而不是下载），需要 Chromium 系浏览器

### 2. 安装依赖

```bash
pnpm install
```

### 3. 构建渲染器的 Node 产物

```bash
pnpm --filter @airp/renderer-target-html build
```

**这一步不是可选的。** 渲染服务加载的是渲染器**编译后**的 Node 产物，没有它预览无法渲染，右栏会直接告诉你要构建什么。改了渲染器却没重建，就会一声不响地渲染旧字节；开发服务器在能看出来时会警告（`renderServicePlugin({ rendererRoot })` 会比较 `src` 与 `dist` 的 mtime），而

```bash
pnpm --filter @airp/renderer-target-html dev
```

可以在开发时常驻，保持产物最新。

### 4. 启动

```bash
pnpm --filter airp-notion dev
```

打开 <http://localhost:5173/>。

开发服务器把渲染端点挂在 `POST /__airp/render`。预览栏是一个普通的 `srcdoc` frame，向这个 URL 发请求；浏览器面从不 import 渲染器，因为包边界不允许 web 宿主进入 `node` 平台。

### 命令

| 命令 | 作用 |
| --- | --- |
| `pnpm --filter airp-notion dev` | 开发服务器（含渲染端点） |
| `pnpm --filter airp-notion build` | 生产构建到 `dist/` |
| `pnpm --filter airp-notion preview` | 预览构建产物（渲染端点同样挂在 preview 上） |
| `pnpm --filter airp-notion test` | 单元测试 + 浏览器端到端测试 |
| `pnpm --filter airp-notion typecheck` | TypeScript 类型检查 |
| `pnpm --filter airp-notion check` | 类型检查 + lint |
| `pnpm check` / `pnpm test` | 整个 workspace |

端到端测试驱动真实 Chromium：它会打字、拖拽把手，并用一个**替身**应对保存选择器 —— 真正的选择器会弹出操作系统对话框，测试无法应答。

## 代码结构

```text
apps/airp-notion/
  src/kernel.ts     路径寻址、纯函数增删改移、句柄、回写
  src/schema.ts     从 document.schema.json 读出块类型与字段
  src/blocks.ts     46 个块的中文名（取自 README.cn.md）与菜单分组
  src/preview.ts    请求 /__airp/render 并显示返回结果
  src/stamp.ts      文档的名字、时间戳、文件名
  src/main.ts       页面：编辑器、操作行、菜单、把手、保存
```

两个值得知道的决定：

- **文档内核放在这个 app 里，不抽成共享包。** 这个 app 的目标是自成一体；唯一共享的是渲染服务 —— 因为"预览与导出不一致"比没有预览更糟。
- **页面拥有文档，预览栏只负责显示。** 在字段里打字只写进文档、**不重绘编辑器**，所以光标永远不会被抢走。结构性变化（插入、删除、移动、转换类型）才会重绘，因为这一列的形状变了。

## 还没做的部分

按重要性大致排序的诚实清单：

- **`Enter` 不会续同类块。** 在新行上按 `Enter` 什么也不会发生：没有"下一个列表项"，没有"空列表项回车退出列表"，也没有 `Tab` 缩进。这是当前与 Notion 手感差距最大的一处。
- **结构化字段还不能编辑。** 46 个类型里有 **44 个**带数组或对象字段。**持有块的数组字段**会渲染成可编辑的嵌套块；其余的（列表项、表格的行列、接口清单、文件树）显示为 `N 项 · 暂不可在此编辑`。
- **无法在中间插入。** 加块是操作行的职责，所以块只会追加在末尾。在块菜单里加一项"在下方插入"就能覆盖这个需求，而且不需要在每一行旁边恢复一个把手。
- **无法在容器内部创建块。** `section`、`group`、`collapsible` 这些会渲染它们的子块，导入的文档也能显示，但编辑器没有提供"新增一个子块"的入口。
- **拖拽不跨层级。** 把块拖进 `section` 是有意不支持的。
- **一次只有一份文档。** 没有标签页、没有最近文件、没有文档树。
- **预览隐藏了导出的外壳**，所以它与 `airp-render` 是**内容一致**、而非**整页一致**。要显示完整页面只需改一行 CSS，代价是协议徽标、标题、时间戳会在窗口左右各出现一次。
